# EventLogger

Микросервис сбора событий всей системы. Слушает обменник `services` целиком
и группирует сообщения по сквозному идентификатору бизнес-транзакции
(`payload.attachment_id` — ADR-0004), то есть по товарному чеку.

## Как собираются события

Очередь `event_logger.in` привязана к topic-обменнику `services` маской
маршрутных ключей `#`, поэтому сервис получает копию каждого сообщения
конвейера, не вмешиваясь в его работу и не требуя изменений в остальных
микросервисах.

Каждое сообщение сохраняется как событие (`events`) и подшивается к чеку
(`checks`) с тем же correlation-id. Чек накапливает сведения о вложении
(имя файла, путь в S3, распознанную стоимость), действие последнего события,
границы обработки и число ошибок. Микросервис-источник события определяется
по действию сообщения (`Events::DetectSourceService`): для `recognized_result`
и `pay_register` продюсеров двое, поэтому они различаются по форме payload.

Порядок событий задаётся полем `created_at` конверта сообщения (время создания
в микросервисе-источнике), а не временем записи в журнал.

## Панель администрирования

ActiveAdmin доступен без авторизации:

- **Чеки** — список бизнес-транзакций, внутри чека хронология всех событий
  системы по нему с задержками между шагами и полными телами сообщений;
- **События** — сквозной журнал с фильтрами по действию, микросервису-источнику,
  correlation-id и признаку ошибки;
- **Главная страница** — сводка по журналу.

## Точки входа

Приложение имеет две точки входа. Пользователи могут обращаться к системе администрирования через HTTP, для этого запускается веб-сервер puma

```bash
bundle exec rails s
```

Кроме того, приложение слушает RabbitMQ-сообщения, для этого поднимается sneakers-обработчик

```bash
bundle exec rails sneakers:run
```

## RabbitMQ

Панель управления RabbitMQ можно найти по ссылке http://localhost:15672/

## Запуск в docker

Подготовка

```bash
docker compose build
```

```bash
COMPOSE_DOCKER_CLI_BUILD=1 DOCKER_BUILDKIT=1 docker compose run -e "RAILS_ENV=development" event-logger bundle exec rake db:drop db:create db:migrate
```

Запуск:

```bash
docker compose up
```

Доступ к командной строке:

```bash
docker compose exec -it event-logger bash
```

## Тестовое сообщение

Задача публикует цепочку событий одного чека прямо в очередь сервиса, не
затрагивая остальные микросервисы:

```bash
docker compose exec event-logger bundle exec rake fake_message:start
```
